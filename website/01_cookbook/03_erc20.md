# Read an ERC-20

Reading a token prompts nobody and costs no gas: `eth_call` is evaluated against
the node's state and never broadcast. So this demo is safe to leave running —
paste any token contract and it will answer.

<Island name="token" trigger="load" />

## The preset

```moonbit
async fn holdings(
  wallet : @browser.BrowserProvider,
  address : @endor.Address,
  who : @endor.Address,
) -> Unit {
  try {
    let token = @erc20.Erc20::new(address)
    // four eth_calls, no prompt and no gas: reads cost the user nothing
    let decimals = token.decimals(wallet)
    let amount = token.balance_of(wallet, who)
    println("\{who} holds \{amount} of \{token.name(wallet)} (\{token.symbol(wallet)})")
    println("its amounts carry \{decimals} decimals")
  } catch {
    Abi(e) => println("that address is not an ERC-20: \{e}")
    Rpc(e) => println("the wallet said: \{e}")
    // `ContractError` has a third variant, `Deployment`, which only `deploy`
    // raises — leaving it out here is a warning, not an oversight the compiler
    // lets pass
    e => println("error: \{e}")
  }
}
```

`Erc20` lives in its own package — `poteto0/endor/contract/erc20`, spelled
`@erc20.Erc20` — because it is a preset over `Contract` rather than part of the
contract layer proper. `Contract` itself is `@contract.Contract`, in
`poteto0/endor/contract`.

The whole interface is there: `name`, `symbol`, `decimals`, `total_supply`,
`balance_of`, `allowance`, `transfer`, `approve`, and `Erc20::transfer_topic()`
for finding transfers in a receipt's logs.

## Showing a balance

`balance_of` answers a `BigInt` in the token's own smallest unit. It is not
divided by anything, because only `decimals` says what to divide by, and USDC has
six where most tokens have eighteen. `Wei::to_units` is where that division
lives — the type is named for ether's unit, but the scaling is the same
arithmetic for any token:

```moonbit
async fn show_balance(
  wallet : @browser.BrowserProvider,
  address : @endor.Address,
  who : @endor.Address,
) -> Unit {
  try {
    let token = @erc20.Erc20::new(address)
    // two reads: what the token's amounts mean, and how many `who` holds
    let decimals = token.decimals(wallet)
    let units = token.balance_of(wallet, who)
    let amount = @endor.Wei::from_bigint(units).to_units(decimals~)
    println("\{amount} \{token.symbol(wallet)}")
  } catch {
    Abi(e) => println("that address is not an ERC-20: \{e}")
    e => println("error: \{e}")
  }
}
```

Trailing zeros are folded, so a round balance reads `"25"` rather than
`"25.000000"`. Padding it back out to a fixed width, grouping the thousands or
putting a symbol in front of it is the application's job — `to_units` returns the
number and stops there.

Read `decimals` once and hold it. It cannot change, and asking again before every
amount is a round trip to be told the same thing.

## Transferring

`transfer` and `approve` sign, so they prompt and answer with a `TxHash` whose
success is in the receipt:

```moonbit
/// 1.5 of a token, in its own units — `None` when that is not an amount the
/// token can carry, which is a token declaring no decimals at all. Its own
/// failure, and not the wallet's, so it is caught here rather than widening the
/// `catch` below past `ContractError`.
fn one_and_a_half(decimals : Int) -> BigInt? {
  Some(@endor.Wei::from_units("1.5", decimals~).to_bigint()) catch { _ => None }
}

async fn send_tokens(
  wallet : @browser.BrowserProvider,
  address : @endor.Address,
  from : @endor.Address,
  to : @endor.Address,
) -> Unit {
  try {
    let token = @erc20.Erc20::new(address)
    let decimals = token.decimals(wallet)
    guard one_and_a_half(decimals) is Some(amount) else {
      println("this token counts whole units only")
      return
    }
    let hash = token.transfer(wallet, from~, to~, amount~) // prompts
    println("broadcast as \{hash}")
  } catch {
    Rpc(e) => println("the wallet said: \{e}")
    Abi(e) => println("that is not an ERC-20: \{e}")
    e => println("error: \{e}")
  }
}
```

A `transfer` that reverts — insufficient balance, a token that refuses — still
gets mined and still costs gas. [Wait for a receipt](./receipts/) is how you find
out which happened.

## When it is not a token

`Abi(e)` is the branch that matters, and it means the address answered but not
the way an ERC-20 does. Almost always that is an address holding no contract at
all, or holding one that is not a token. Retrying does not help:

```moonbit
async fn is_it_a_token(
  wallet : @browser.BrowserProvider,
  address : @endor.Address,
) -> Bool {
  // `is_contract` is `eth_getCode` with an emptiness test — an externally owned
  // account has no bytecode, and asking it for `symbol()` can only fail
  guard (@provider.is_contract(wallet, address) catch { _ => false }) else {
    return false
  }
  let _ = @erc20.Erc20::new(address).symbol(wallet) catch {
    _ => return false
  }
  true
}
```
